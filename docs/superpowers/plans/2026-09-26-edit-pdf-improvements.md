# แผนปรับปรุง Edit PDF

วันที่: 2026-09-26
สถานะ: ลงมือพัฒนาชุดแกนกลางและฟีเจอร์ export รอบแรกแล้ว; รายการที่ยังไม่ลงมือระบุไว้ท้ายเอกสาร

ความคืบหน้า: ทำแล้ว — เปลี่ยนเครื่องมือโดยคงเอกสาร, draft ใน IndexedDB, กู้คืนหลังรีเฟรช, history/source lifecycle, progress/cancel, ซูม, ไปหน้า, เลือกช่วง, หน้าว่าง, preset ตัดขอบหน้า, ลายน้ำ, เลขหน้า, ข้อความหลายบรรทัด, ไฮไลต์, ขีดเส้น, โน้ต, บีบอัดแบบ raster และความละเอียดส่งออกเป็นรูป

## เป้าหมายและขอบเขต

ทำรายการทั้งหมดในหมวด 1 (พื้นฐานที่จำเป็น 6 รายการ) และหมวด 2 (ฟีเจอร์ใหม่ 7 รายการ) ตามที่ผู้ใช้เลือก โดยคงหน้าตาและระบบธีมเดิมของโปรเจกต์ ใช้เอกสารชุดเดียวต่อเนื่องระหว่างเครื่องมือ และประมวลผลเอกสารในเบราว์เซอร์

ผู้ใช้หลักคือผู้จัดเตรียมเอกสารทั่วไป: รวมไฟล์ จัดหน้า เติมข้อความ เซ็นชื่อ ทำเครื่องหมาย แล้วดาวน์โหลด โดยต้องกลับมาแก้ต่อได้และไม่เสียงานเมื่อเปลี่ยนเครื่องมือ

หมวด 3 ยังอยู่นอกขอบเขตรอบนี้: แก้ข้อความต้นฉบับ, OCR, redaction, รหัสผ่าน, ฟอร์ม PDF และ Word/Excel conversion ทั้งนี้ต้องบอกในเครื่องมือข้อความว่าเป็นการเพิ่มข้อความลงบนหน้า

## ฐานโค้ดและข้อค้นพบ

- `app/dashboard/programs/edit-pdf/page.tsx`: state เอกสาร, ประวัติ, import/export, เลือกเครื่องมือ และตั้งค่าผลลัพธ์รวมอยู่ในหน้าเดียว
- `components/pdf-editor/pdf-editor.types.ts`: มี page references และ placements แบบ text/image; ต้องขยายให้รองรับหน้าว่าง การครอป ขนาดกระดาษ และ annotation
- `components/pdf-editor/pdf-utils.ts`: โหลดไฟล์, สร้างภาพ, เปลี่ยนข้อมูลหน้า และสร้างไฟล์ผลลัพธ์ ใช้ pdf-lib/pdfjs/fontkit/JSZip ที่ติดตั้งอยู่
- `components/pdf-editor/PdfPageEditor.tsx`: วางข้อความ รูปและลายเซ็น มีลากย้ายและปรับขนาด แต่ไม่มี zoom controls
- `components/pdf-editor/PdfPageGrid.tsx`: thumbnail grid และจัดการหน้า
- ปุ่มกลับเครื่องมือเรียก `reset` ซึ่งล้างเอกสารและประวัติ
- ปุ่ม Undo/Redo ตรวจว่ามีหน้าแทนการตรวจประวัติ ทำให้กรณีลบทุกหน้าใช้งาน Undo ผ่านปุ่มไม่ได้
- `removeSource` ลบ bytes และ document proxy ทันที แต่ history ยังอ้างหน้าของ source นั้นอยู่ ต้องแก้ก่อนต่อยอด draft/history
- ประเมินจาก source code ยังไม่ได้ทดสอบหน้าจอหรือยืนยันสมรรถนะจริง

## แนวทางโครงสร้าง

1. แยก document state/history ออกจาก UI เครื่องมือด้วย hook หรือ reducer; เครื่องมือเปลี่ยนเฉพาะโหมดการทำงาน
2. เก็บ source bytes และ image assets แยกจาก snapshots ด้วย asset ID; ไม่ทำสำเนาไฟล์ใหญ่ทุกครั้งที่แก้ข้อความ
3. เก็บ source ที่ history/future ยังอ้างถึง และล้างเมื่อไม่มี references เหลือหรือปิดเอกสารจริง
4. จัด operation ที่เกิดจากการกระทำหนึ่งครั้งเป็นหนึ่งรายการ Undo เช่น ลากหนึ่งครั้ง พิมพ์ต่อเนื่องหนึ่งช่วง หรือใส่ลายน้ำหลายหน้า
5. ใช้ระบบพิกัดหน้าและการแปลงพิกัดร่วมกันสำหรับ preview/export ทั้ง PDF และรูปภาพ รวม rotation/crop/resize/zoom
6. ตั้งเวอร์ชัน schema ของ draft และตรวจความสมบูรณ์ก่อน restore; ไม่ serialize PDFDocumentProxy, canvas หรือ object URL
7. งาน import/render/export มี task ID และจุดตรวจยกเลิก เพื่อไม่ให้ผลจากงานเก่ากลับมาเขียนทับงานใหม่

## เฟส 1 — เอกสารต่อเนื่อง ประวัติถูกต้อง และกู้คืนงาน

งาน:

- แยก state เอกสารออกจาก selected tool และแยกคำสั่ง “เครื่องมือทั้งหมด” ออกจาก “เริ่มเอกสารใหม่”
- เปลี่ยนเครื่องมือแล้วคงไฟล์ หน้า ลายเซ็น ข้อความ ชื่อผลลัพธ์ และประวัติ
- เพิ่ม `canUndo`/`canRedo` จาก history จริง รวมกรณีลบทุกหน้า
- แก้ source lifecycle ให้ undo การเอาไฟล์ออกแล้วเรนเดอร์และ export ได้
- บันทึก draft ใน IndexedDB แบบ debounce พร้อมไฟล์ต้นทาง assets และการตั้งค่า; เก็บ history แบบจำกัดและใช้ asset references
- แสดงสถานะ “กำลังบันทึก / บันทึกในเครื่องแล้ว / บันทึกไม่สำเร็จ” และเสนอ “ทำงานต่อ / เริ่มใหม่” เมื่อพบ draft
- มีลบ draft และเริ่มใหม่อย่างชัดเจน; ไม่อ้างว่าบันทึกสำเร็จจน transaction สำเร็จ
- เตือนก่อนทิ้งงานที่ยังไม่ได้ส่งออกเมื่อเริ่มใหม่หรือออกจาก editor; ใช้ beforeunload เป็นการป้องกันเสริมสำหรับปิด/รีเฟรช และจัดการ navigation ภายในแอปตาม router จริง
- บันทึกระหว่างทำงาน ไม่รอเขียนข้อมูลตอนปิดแท็บ; หาก storage เต็มหรือใช้งานไม่ได้ยังทำงานและดาวน์โหลดต่อได้ พร้อมแจ้งสถานะจริง

เกณฑ์ตรวจรับ:

- รวม → จัดหน้า → เติมข้อความ → กลับเครื่องมือ → แยกไฟล์ได้โดยไม่ต้องเปิดไฟล์ใหม่
- รีเฟรชหลังสถานะบันทึกสำเร็จแล้วคืนหน้า ลำดับ rotation placements และชื่อไฟล์ได้
- เอา source ออกแล้ว Undo และ export ได้; ลบทุกหน้าแล้ว Undo ผ่านปุ่มได้
- ยกเลิก dialog ทิ้งงานแล้วข้อมูลเดิมอยู่ครบ; storage error ไม่ทำให้ editor ใช้งานไม่ได้

## เฟส 2 — ซูม เลือกหน้า และสถานะการทำงาน

งาน:

- เพิ่มซูม 25–400%, 100%, พอดีหน้า, พอดีความกว้าง และเลื่อน canvas โดยไม่รบกวนการลากวัตถุ
- ปรับความละเอียด render ตามระดับ zoom โดยจำกัดขนาด canvas/memory; ไม่เปลี่ยนพิกัดที่บันทึกในเอกสาร
- เพิ่มช่องไปหน้าและเลือกช่วง `1-5, 8, 12`; ตรวจรูปแบบ ค่าติดลบ เกินจำนวนหน้า และรวมหน้าซ้ำ
- แยกตัวอ่านช่วงสำหรับ “เลือกหน้า” กับการแบ่งกลุ่มใน Split เพื่อไม่เปลี่ยนความหมายของ split เดิม
- เพิ่ม progress ตามขั้นตอนและจำนวนหน้าที่ทำเสร็จ พร้อม Cancel; ขั้นตอนที่วัดไม่ได้ให้แสดงกำลังทำงานแทนเปอร์เซ็นต์สมมติ
- ยกเลิกงาน render ที่ API รองรับ และตรวจ abort ระหว่างหน้า; ขั้นตอนที่หยุดกลางคันไม่ได้ให้ยกเลิกผลลัพธ์และป้องกัน stale updates
- ป้องกัน export ซ้ำ และกำหนดให้ export ใช้ snapshot เดียวตั้งแต่ต้นจนจบ
- โหลด thumbnail ตามความจำเป็นและจำกัดงานพร้อมกัน; ขยายเป็น virtualization หากผลทดสอบไฟล์ยาวบ่งชี้ว่าจำเป็น

เกณฑ์ตรวจรับ:

- วางและลากลายเซ็นที่หลายระดับ zoom แล้วตำแหน่ง export ตรง preview รวมหน้าหมุน
- ไปหน้าแรก/สุดท้ายและเลือกช่วงทำงานถูกต้อง; input ผิดแสดงเหตุผลโดยไม่เลือกหน้าอื่นแทนเงียบ ๆ
- Cancel ระหว่าง import/export แล้วไม่มีไฟล์ผลลัพธ์บางส่วนถูกดาวน์โหลด ไม่มีผลเก่าเขียนทับ และเริ่มงานใหม่ได้

## เฟส 3 — ครอป หน้าว่าง ขนาดกระดาษ และรูป↔PDF

ทำ geometry ของหน้าก่อนเครื่องมือที่ต้องจัดตำแหน่งหลายหน้า เพื่อใช้พิกัดร่วมกัน

งาน:

- เพิ่มหน้าว่างก่อน/หลังหน้าที่เลือก เลือก A4/A3/Letter และแนวตั้ง/แนวนอน
- เพิ่ม crop แบบลากกรอบพร้อมตัวเลข ใช้กับหน้าเดียวหรือหลายหน้าที่เลือก และรีเซ็ตได้
- crop เป็นการเปลี่ยนพื้นที่แสดงผลของหน้า ไม่ใช่การลบข้อมูลถาวร; ระบุความหมายสั้น ๆ ใน UI
- เปลี่ยนขนาดกระดาษโดยเลือกพอดีพื้นที่และคงสัดส่วน พร้อมระยะขอบ; ไม่ยืดข้อความหรือรูปผิดสัดส่วน
- กำหนด transform ของ placements ให้ตามเนื้อหาเมื่อ resize และให้ preview/export ใช้กฎเดียวกัน
- รูป→PDF: ขนาดตามรูปหรือกระดาษมาตรฐาน, แนวกระดาษ, margin, fit/เติมเต็มพร้อม preview การตัดขอบ
- PDF→รูป: PNG/JPG, เลือกหน้า, 72/150/300 DPI และคุณภาพ JPG; แสดงขนาดภาพที่คาดได้และคุม canvas limit

เกณฑ์ตรวจรับ:

- export แล้วขนาดหน้าและกรอบ crop ถูกต้อง; Undo/Redo ใช้ได้กับทุกคำสั่งใหม่
- เอกสารหลายขนาดและหน้าหมุนมี preview ตรงกับ PDF/ภาพผลลัพธ์
- รูปไม่เสียสัดส่วน ระยะขอบถูกต้อง และตัวเลือกคุณภาพมีผลต่อผลลัพธ์จริง

## เฟส 4 — ข้อความ ลายน้ำ ตราประทับ และเลขหน้า

งาน:

- เพิ่มกล่องข้อความหลายบรรทัด ตัดบรรทัดตามความกว้าง จัดซ้าย/กลาง/ขวา และตัวหนา
- เพิ่มฟอนต์ไทยน้ำหนักที่ใช้จริงพร้อมไฟล์ license; preview และ export ใช้ font metrics/layout ชุดเดียวกัน
- คัดลอก/วาง/ทำสำเนาวัตถุ และใช้กับหลายหน้าหรือทุกหน้า โดยวางตามตำแหน่งสัดส่วนบนหน้าปลายทาง
- ลายน้ำข้อความ/รูป: ความโปร่งใส มุม ขนาด ตำแหน่ง และขอบเขตหน้า
- ตราประทับเริ่มต้น “สำเนาถูกต้อง”, “ฉบับร่าง” และข้อความกำหนดเอง; ผู้ใช้ยังแก้ไขหรือลบได้
- เลขหน้าและ header/footer: ตำแหน่งซ้าย/กลาง/ขวา, `1` หรือ `1 / N`, เลขเริ่มต้น และช่วงหน้าที่ใช้งาน
- เลขหน้าอ้างลำดับปัจจุบันของเอกสารและอัปเดตหลัง reorder/delete; UI แสดงตัวอย่างก่อนนำไปใช้
- รวมการเพิ่มหลายหน้าเป็น Undo ครั้งเดียว และทำให้การกดแก้ไขไม่สร้างรายการซ้ำโดยไม่ตั้งใจ

เกณฑ์ตรวจรับ:

- ภาษาไทย สระ/วรรณยุกต์ ตัวหนา และหลายบรรทัดตรงกันระหว่าง preview กับผลลัพธ์ที่เปิดใน viewer
- สลับหรือลบหน้าแล้วเลขหน้า/จำนวนหน้าถูกต้อง
- ใส่ลายน้ำในช่วงที่เลือกแล้วไม่มีหน้าอื่นได้รับผล; Undo หนึ่งครั้งคืนการเปลี่ยนแปลงทั้งชุด

## เฟส 5 — ไฮไลต์ ขีดเส้น วาด และโน้ต

งาน:

- เพิ่ม annotation types สำหรับ highlight rectangle, line/underline, freehand path และ note
- ไฮไลต์รอบแรกใช้ลากพื้นที่; การเลือกคำจาก text layer ไม่อยู่ในรอบนี้และป้ายเครื่องมือต้องสื่อให้ตรง
- ตั้งสี ความหนา และความโปร่งใสตามชนิด; เลือก ย้าย ลบ และ Undo/Redo ได้
- โน้ตมีข้อความแก้ไขได้และตำแหน่งบนหน้า; แสดงรายการโน้ตของหน้าปัจจุบัน
- PDF/รูปผลลัพธ์ต้องแสดงเนื้อหาโน้ตอ่านได้ เช่นกล่องข้อความบนหน้า ไม่ส่งออกเพียงไอคอนที่ไม่มีข้อความ
- รอบนี้ส่งออกเครื่องหมายเป็นส่วนหนึ่งของหน้ากระดาษ; draft เก็บวัตถุแก้ต่อได้ การทำ PDF comments แบบตอบกลับในโปรแกรมอื่นเป็นงานแยก
- รองรับ pointer ของเมาส์/ปากกา/สัมผัส และป้องกันการวาดพลาดขณะเลื่อนหน้า

เกณฑ์ตรวจรับ:

- ทุกชนิดแสดงใน PDF และรูปที่ส่งออก พร้อมตำแหน่งและสีถูกต้องหลังหมุน/ครอป/resize
- เปิด draft แล้วแก้ไข annotation ต่อได้ และ Undo/Redo ครบ

## เฟส 6 — บีบอัด PDF พร้อมเปรียบเทียบคุณภาพ

ขอบเขตที่ทำได้ชัดเจนในรอบนี้คือโหมดลดขนาดโดยแปลงหน้าเป็นภาพ เหมาะกับเอกสารสแกน ต้องไม่โฆษณาว่าลดขนาดได้ทุกไฟล์หรือรักษา text layer

งาน:

- ทดลองกับไฟล์สแกนและไฟล์ข้อความก่อนล็อกค่าคุณภาพ เพื่อวัดขนาด เวลา และความอ่านง่ายจริง
- ตัวเลือกคุณภาพสูง/สมดุล/ไฟล์เล็ก ผูกกับ DPI และ JPEG quality ที่ได้จากการทดลอง
- แสดงข้อความก่อนใช้ว่าไฟล์ผลลัพธ์เป็นภาพ ข้อความจะเลือก/ค้นหาไม่ได้ และองค์ประกอบโต้ตอบอาจไม่คงอยู่
- สร้าง preview เปรียบเทียบหน้าเดียวก่อนประมวลผลทั้งไฟล์; วัดขนาดจริงก่อน/หลังและแสดงเปอร์เซ็นต์ลดลง
- หากไฟล์ใหญ่ขึ้น ให้บอกว่าขนาดไม่ลดและให้เลือกดาวน์โหลด PDF ปกติได้ ไม่แสดงความสำเร็จว่าบีบอัดแล้วเล็กลง
- ประมวลผลเป็นหน้า ๆ ปล่อย canvas/buffer เมื่อไม่ใช้ พร้อม progress/Cancel
- เก็บเอกสารที่แก้ไขอยู่ไว้เหมือนเดิม; compression เป็นทางเลือก export ที่ลองซ้ำได้
- หากต้องการบีบอัดโดยรักษาข้อความและเวกเตอร์ ให้เปิดงานประเมิน engine เพิ่มต่างหากก่อนสัญญาความสามารถนี้

เกณฑ์ตรวจรับ:

- fixture เอกสารสแกนที่เหมาะสมมีขนาดลดลงและยังอ่านภาษาไทยได้ตามระดับคุณภาพที่เลือก
- preview บอกผลแลกเปลี่ยนชัดเจน ขนาดที่รายงานตรงกับไฟล์ดาวน์โหลด และยกเลิกได้โดยไม่เสียเอกสารที่กำลังทำงาน

## เฟส 7 — ตรวจรวมและเก็บรายละเอียดก่อนส่งมอบ

- ทดสอบ workflow รวม → จัดหน้า → ครอป → เพิ่มข้อความ/ลายเซ็น → เลขหน้า/ลายน้ำ → โน้ต → บันทึก draft → restore → export
- ตรวจ desktop และจอแคบ: toolbar, panel, dialog, keyboard focus, labels และ touch targets
- ตรวจ PDF ที่ส่งออกด้วย PDF.js และ browser viewer; ตรวจ viewer อื่นเท่าที่มีให้ใช้และบอกข้อจำกัดหากไม่ได้ตรวจ
- ใช้ fixtures: ไทย/อังกฤษ, หน้าหมุนทุกมุม, page boxes มี origin ไม่เป็นศูนย์, หลายขนาด, สแกน, หน้าว่าง, ไฟล์เสีย, ไฟล์ล็อก, หลาย source และเอกสารยาว
- ทดสอบเชิงพฤติกรรมเฉพาะส่วนเสี่ยง: history/source lifecycle, draft restore/storage failure, range parser, geometry, page numbering, cancellation และ export round-trip
- วัดเวลาเปิดและส่งออกบนเครื่องทดสอบด้วยเอกสารตัวแทน 10/100/300 หน้า รวมไฟล์เกิน 50 MB; บันทึกเงื่อนไขและผลจริงก่อนตั้งข้อจำกัด
- ตรวจด้วย typecheck และ production build ตามเครื่องมือของ repository; ตรวจ lint configuration ก่อนใช้ เพราะ script ปัจจุบันเป็น `next lint`
- ตรวจ network ว่าไม่มี bytes เอกสารถูกอัปโหลดโดยฟังก์ชันใหม่; โหลดฟอนต์/worker จาก asset ของแอปตามเดิม

## ไฟล์ที่คาดว่าจะเปลี่ยนหรือเพิ่ม

- ปรับ `app/dashboard/programs/edit-pdf/page.tsx` ให้เน้นประกอบหน้าจอแทนรวม logic ทุกชนิด
- ปรับ types, utils, PdfPageEditor, PdfPageGrid และส่วนตั้งค่า export
- เพิ่มโมดูลตามความรับผิดชอบ เช่น `usePdfProject`, `pdf-draft-store`, `pdf-geometry`, `pdf-page-ranges`, `pdf-text-layout`, `pdf-export` และ `pdf-compression`
- เพิ่ม components สำหรับ toolbar, progress, restore draft และ panels ของฟีเจอร์ใหม่ตามความเหมาะสม
- เพิ่ม tests/fixtures ของ PDF และปรับเอกสารสถานะฟีเจอร์เมื่อผ่านการตรวจจริง
- ไม่จำเป็นต้องเพิ่ม API route หรือบริการภายนอกสำหรับขอบเขตที่กำหนดนี้
