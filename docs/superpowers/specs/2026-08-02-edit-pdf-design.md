# Edit PDF Program Design

หน้า `/dashboard/programs/edit-pdf` ปัจจุบันเป็น placeholder เอกสารนี้กำหนดขอบเขต v1 แบบ "เอาที่ใช้บ่อยก่อน" — ทำเฉพาะงานที่คนทำเป็นประจำ ทำในเบราว์เซอร์ทั้งหมด ไม่เพิ่ม API route และไม่ต้องติดตั้ง binary ใด ๆ บน server

## Goal

ให้ผู้ใช้ทำงาน PDF ประจำวันจบในหน้าเดียว — รวมไฟล์ จัดหน้า หมุน เซ็นชื่อ แปลงรูป — โดยไฟล์ไม่ต้องออกจากเครื่อง ซึ่งเป็นข้อได้เปรียบเหนือเว็บ PDF ฟรีทั่วไปที่ต้องอัปโหลดเอกสารสำคัญขึ้นไป

## v1 Scope — 6 ฟังก์ชัน

| ฟังก์ชัน | ทำอะไร | ทำไมอยู่ใน v1 |
|---|---|---|
| **Merge** | รวมหลายไฟล์เป็นไฟล์เดียว ลากจัดลำดับไฟล์ได้ | งานที่ใช้บ่อยที่สุดของเครื่องมือ PDF ทุกตัว |
| **จัดหน้า** | ลบ · สลับลำดับ (drag & drop) · หมุน · ทำสำเนา — ทำในหน้าจอเดียวกัน | งานประจำที่คนเปิดเครื่องมือ PDF เพื่อทำ |
| **Split / Extract** | แยกตามช่วงหน้า หรือดึงเฉพาะหน้าที่เลือกออกเป็นไฟล์ใหม่ | ใช้บ่อยพอ ๆ กับ merge และใช้กลไกเดียวกับการจัดหน้า |
| **เซ็นชื่อ** | เซ็นบน canvas / อัปโหลดรูปลายเซ็น แล้วลากไปวางตำแหน่ง + บันทึกลายเซ็นไว้ใช้ซ้ำ | งานที่คนต้องทำแต่เว็บฟรีมักบังคับให้อัปโหลดเอกสารสำคัญ |
| **วางข้อความ / รูป** | วางกล่องข้อความหรือรูปใหม่ทับลงบนหน้า (กรอกฟอร์ม เติมวันที่ ใส่โลโก้) | ใช้กลไกวางของเดียวกับลายเซ็น ได้มาแทบฟรี |
| **รูป ↔ PDF** | รวมรูปหลายไฟล์เป็น PDF และส่งออกหน้า PDF เป็น PNG/JPG | ถ่ายรูปเอกสารแล้วต้องส่งเป็น PDF เป็นงานที่เจอทุกวัน |

ทั้งหมดนี้ `pdf-lib` + `pdfjs-dist` ทำได้ในเบราว์เซอร์ ไม่ต้องมี endpoint ใหม่

## หน้าจอ — มีแค่ 2 หน้า

ไม่ต้องทำ editor เต็มรูปแบบสามคอลัมน์แบบ edit-clip ตั้งแต่แรก ใช้รูปแบบ "เลือกเครื่องมือ → วางไฟล์ → ทำ → ดาวน์โหลด" ซึ่งเข้าใจง่ายกว่าและงานน้อยกว่ามาก

**1. หน้าเลือกเครื่องมือ**

```text
┌──────────────────────────────────────────────────┐
│ Edit PDF          ไฟล์ทั้งหมดทำงานในเครื่องคุณ 🔒  │
├──────────────────────────────────────────────────┤
│  ┌────────┐ ┌────────┐ ┌────────┐               │
│  │ รวมไฟล์ │ │ จัดหน้า │ │  แยกไฟล์ │              │
│  └────────┘ └────────┘ └────────┘               │
│  ┌────────┐ ┌────────┐ ┌────────┐               │
│  │ เซ็นชื่อ │ │ใส่ข้อความ│ │ รูป↔PDF │              │
│  └────────┘ └────────┘ └────────┘               │
│                                                  │
│  ไฟล์ล่าสุด: สัญญา.pdf · ใบเสร็จ.pdf              │
└──────────────────────────────────────────────────┘
```

**2. หน้าทำงาน** (ใช้ร่วมกันทุกเครื่องมือ ต่างกันแค่แถบขวา)

```text
┌──────────────────────────────────────────────────┐
│ ← กลับ   จัดหน้า · สัญญา.pdf      [ดาวน์โหลด PDF] │
├────────────────────────────────────┬─────────────┤
│  ▭ 1   ▭ 2   ▭ 3   ▭ 4   ▭ 5      │ เครื่องมือ   │
│  ▭ 6   ▭ 7   ▭ 8   ▭ 9   ▭ 10     │ ของหน้าที่   │
│      (ลากสลับ · คลิกเลือกหลายหน้า)  │ เลือกอยู่    │
│                                    │             │
│  คลิกหน้าเพื่อเปิดขนาดใหญ่และวางของ  │ [ลบ] [หมุน] │
└────────────────────────────────────┴─────────────┘
```

Grid ของ thumbnail คือหัวใจ — ทั้ง merge, จัดหน้า, split ใช้หน้าจอเดียวกันหมด ต่างแค่ปุ่มด้านขวา ส่วนเซ็นชื่อ/วางข้อความคลิกเข้าไปดูหน้าใหญ่แล้วลากวาง

คีย์ลัดที่ควรมี: `Del` ลบหน้าที่เลือก · `Ctrl+Z/Y` undo/redo · `←/→` เปลี่ยนหน้า

## Data model

```ts
type Rect = { x: number; y: number; w: number; h: number }

type PdfSource = { id: string; name: string; size: number; pageCount: number; encrypted: boolean }

type PdfPageRef = { id: string; sourceId: string; sourceIndex: number; rotation: 0 | 90 | 180 | 270 }

type PdfOperation =
  | { kind: 'append'; pages: PdfPageRef[] }          // เปิดไฟล์เพิ่มเข้ามาในเอกสารเดียวกัน
  | { kind: 'reorder'; order: string[] }
  | { kind: 'delete'; pageIds: string[] }
  | { kind: 'duplicate'; pageIds: string[] }
  | { kind: 'rotate'; pageIds: string[]; degrees: 90 | 180 | 270 }
  // สองอันนี้เพิ่มพร้อมฟังก์ชันเซ็นชื่อ/วางข้อความ ยังไม่ได้ทำ
  | { kind: 'text'; pageId: string; rect: Rect; text: string; size: number; color: string }
  | { kind: 'image'; pageId: string; rect: Rect; dataUrl: string }   // ใช้กับลายเซ็นด้วย

type PdfProject = { id: string; name: string; sources: PdfSource[]; pages: PdfPageRef[]; operations: PdfOperation[] }
```

เก็บ `operations` เป็น list ทำให้ undo/redo คือการ pop/push แบบเดียวกับ `historyRef` ใน edit-clip และตอนส่งออกคือ replay operations ลงไฟล์ทีเดียว เพิ่ม operation ใหม่ทีหลังได้โดยไม่ต้องรื้อโครงสร้าง

## Dependency

- `pdf-lib` — สร้าง/แก้ไข PDF ฝั่ง client
- `pdfjs-dist` — เรนเดอร์ thumbnail และหน้าตัวอย่าง
- `jszip` — แพ็กผลลัพธ์ตอน split เป็นหลายไฟล์
- `@pdf-lib/fontkit` + ฟอนต์ไทย TTF (Sarabun/Noto Sans Thai) ใน `public/` — **จำเป็น** สำหรับฟังก์ชันวางข้อความ

ไม่ต้องเพิ่ม API route ไม่ต้องติดตั้ง binary บน server

worker ของ pdfjs ถูกคัดลอกไว้ที่ `public/pdf.worker.min.mjs` เพื่อให้ `workerSrc` เป็น path คงที่ ใช้ได้ทั้ง webpack และ turbopack **ต้องคัดลอกใหม่ทุกครั้งที่อัปเกรด `pdfjs-dist`**

```bash
cp node_modules/pdfjs-dist/build/pdf.worker.min.mjs public/pdf.worker.min.mjs
```

## ตัดออกจาก v1

เก็บไว้พิจารณาทีหลังเมื่อรู้ว่าผู้ใช้ต้องการจริง — ไม่ต้องออกแบบลึกตอนนี้

| รายการ | เหตุผล |
|---|---|
| **บีบอัดไฟล์** | ใช้บ่อยจริง แต่ต้องมี ghostscript/qpdf บน server ซึ่งพังหลักการ client-only ของ v1 → **ควรเป็นงานแรกของ v2** ถ้าอยากได้เร็วแบบถูก ๆ ทำเฉพาะไฟล์สแกนได้ด้วยการเรนเดอร์เป็น JPEG แล้วประกอบใหม่ (แลกกับข้อความจะเลือกไม่ได้) |
| **ใส่/ถอดรหัสผ่าน** | `pdf-lib` ใส่รหัสผ่านไม่ได้ในตัว ต้องหา library เพิ่ม — รอดูความต้องการก่อน |
| **แก้ข้อความเดิมในไฟล์** | คนอยากได้มากที่สุด แต่ยากที่สุด ต้องอ่าน text layer + ทับพื้นหลัง + redaction และยังไม่ reflow — เป็นงานก้อนใหญ่ของตัวเอง ไม่ควรปนมาใน v1 |
| ลายน้ำ · เลขหน้า · header/footer | ใช้กลไกเดียวกับ `text`/`image` เพิ่มทีหลังได้ในไม่กี่ชั่วโมง |
| OCR · AI สรุป/ถาม-ตอบ · ดึงข้อมูลเป็น CSV | ต้องใช้ server และ AI service |
| แปลงเป็น Word/Excel · Office→PDF | ต้องมี LibreOffice บน server |
| ฟอร์ม · batch หลายไฟล์ · share link | ยังไม่มีสัญญาณว่าจำเป็นตั้งแต่แรก |

## ข้อควรระวัง

- **ฟอนต์ไทย**: ใช้ Sarabun (OFL) ที่ `public/fonts/Sarabun-Regular.ttf` ฝังลงไฟล์แบบ subset เฉพาะตอนที่มีข้อความจริง
- **การจัดวางวรรณยุกต์**: `pdf-lib` เรียก `fontkit.layout()` จึงได้ glyph ที่ผ่าน GSUB มาถูกต้อง แต่มันหยิบไปแค่ `glyphs[].id` ทิ้งค่า GPOS offset ตรวจกับ Sarabun แล้วพบว่า `yOffset` เป็น 0 ทุกตัว (ฟอนต์ฝังตำแหน่งไว้ในตัว glyph อยู่แล้ว) สระบน/ล่างจึงไม่ลอยผิดที่ เหลือแค่ `xOffset` บางพยางค์ที่คลาดได้ถึง ~14% em เช่น "ปุ๋ย" ถ้าวันหนึ่งต้องเป๊ะกว่านี้ ทางออกคือวาดข้อความเป็นภาพแทน
- **หน้าที่ถูกหมุน**: หน้าจอวางของแสดงหน้าแบบไม่หมุนเสมอ เพื่อให้พิกัดบนจอตรงกับพิกัดใน PDF หนึ่งต่อหนึ่ง ของที่วางจะติดไปกับกระดาษและหมุนตามตอนบันทึก
- **ไฟล์ใหญ่**: เกิน ~50MB หรือหลายร้อยหน้าจะกิน memory ใน browser — v1 แค่ตรวจขนาดแล้วเตือนก่อนเปิดก็พอ ยังไม่ต้องทำ virtualization
- **ไฟล์ที่ล็อกอยู่**: ตรวจ `encrypted` ตอนเปิดไฟล์แล้วแจ้งผู้ใช้ ไม่ปล่อยให้ทำงานแล้ว fail เงียบ ๆ

## สถานะการทำ

ทำครบทั้ง 6 ฟังก์ชันของ v1 แล้ว — `components/pdf-editor/` + `app/dashboard/programs/edit-pdf/page.tsx`

**ก้อนที่ 1 — ฐานและจัดการหน้า**
หน้าเลือกเครื่องมือ · เปิดหลายไฟล์ · thumbnail grid · ลากสลับลำดับ · ลบ/หมุน/ทำสำเนา · เลือกหลายหน้า (Shift+คลิก) · undo/redo · คีย์ลัด · รวมไฟล์ · แยกไฟล์ 4 แบบ · ดาวน์โหลดเป็น PDF หรือ ZIP

**ก้อนที่ 2 — เซ็นชื่อและวางข้อความ**
หน้าจอวางของรายหน้า (`PdfPageEditor`) · กล่องข้อความไทยด้วยฟอนต์ Sarabun ที่ฝังลงไฟล์ · วางรูป · เซ็นบน canvas หรืออัปโหลดลายเซ็น พร้อมจำลายเซ็นไว้ใช้ซ้ำใน localStorage · ลากย้าย/ย่อขยาย · แก้ข้อความ ขนาด สี

**ก้อนที่ 3 — รูป ↔ PDF**
รวมรูป JPG/PNG เป็น PDF (หนึ่งรูปต่อหนึ่งหน้าขนาดเท่ารูป) แล้วไหลเข้าไปป์ไลน์เดียวกับ PDF ปกติ · ส่งออกหน้าเป็น PNG/JPG พร้อมวาดของที่วางไว้ทับให้ตรงกับไฟล์ PDF

**ตรวจด้วยการรันจริงแล้ว** — หมุน/ทำสำเนา/ลบ/ลากสลับลำดับแล้ว export ได้ไฟล์ที่ pdfjs อ่านกลับถูกต้องทั้งลำดับและค่าหมุน · split ได้ ZIP ตามช่วงที่ระบุ · content stream ของไฟล์ที่มีลายเซ็นและข้อความไทยมี `Tf` ฟอนต์ Sarabun ที่ฝังไว้ ตำแหน่ง baseline ตรงสูตร และมี `Do` ของรูปตามขนาดที่ตั้ง · รวมรูปเป็น PDF ได้ขนาดหน้าตรงกับรูปต้นฉบับ

**ยังไม่ได้ตรวจด้วยตา** — ทุกอย่างที่ต้องเรนเดอร์ภาพ (thumbnail, ภาพหน้าในหน้าจอวางของ, ส่งออกเป็นรูป) เพราะ pdfjs เดิน render loop ด้วย `requestAnimationFrame` ซึ่งไม่ทำงานเมื่อแท็บถูกซ่อน

## Acceptance criteria

- ทำ 6 ฟังก์ชันของ v1 ได้ครบโดยไม่มีการอัปโหลดไฟล์ออกจากเบราว์เซอร์
- ทุกการแก้ไขผ่าน `PdfOperation` ชุดเดียว และ undo/redo ได้ครบทุกชนิด
- ไฟล์ที่ส่งออกเปิดได้ถูกต้องใน Acrobat, Chrome และ Preview
- ข้อความภาษาไทยที่วางลงไปแสดงผลถูกต้องในทุก viewer
- หน้าจอบอกชัดว่าไฟล์ทำงานในเครื่องผู้ใช้ ไม่ได้ถูกอัปโหลด
